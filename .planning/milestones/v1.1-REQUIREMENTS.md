# Requirements Archive: v1.1 Timeline & Planner UX Polish

**Archived:** 2026-06-07
**Status:** All requirements shipped ✅

---

## LAYOUT — Timeline Correctness

- [x] **LAYOUT-01** — Task block height is proportional to duration (hourHeight px per hour), so a 30-min task is visually half the height of a 1-hour task
  - Delivered: Phase 08 — PX_PER_HOUR=80, usePlannerTimeline duration calc, DailyPlannerView

- [x] **LAYOUT-02** — Task blocks are vertically positioned at the correct time offset from midnight (top = startMinutes / 60 * hourHeight)
  - Delivered: Phase 08 — PX_PER_HOUR=80, correct top calculation in DraggableTimeBlock/PlannerTimeBlock

- [x] **LAYOUT-03** — Planner view auto-scrolls to center the current time in the viewport when opened
  - Delivered: Phase 08 — useEffect with scrollIntoView on currentTimeRef in DailyPlannerView (now TimelineCanvas)

## DRAG — Drag to Reschedule

- [x] **DRAG-01** — User can drag a task block vertically to change its startAt, with the block snapping to 15-minute intervals during drag
  - Delivered: Phase 09 — useDragToReschedule startMove, snapToGrid(15), DraggableTimeBlock

- [x] **DRAG-02** — User can drag the bottom edge of a task block to resize its duration, snapping to 15-minute intervals
  - Delivered: Phase 09 — useDragToReschedule startResize, resize handle in DraggableTimeBlock

- [x] **DRAG-03** — Drag and resize changes are persisted to the backend on pointer/touch release with optimistic update and revert-on-failure
  - Delivered: Phase 09 — onReschedule/onResize → PATCH /api/tasks/:id, revert animation on failure

- [x] **DRAG-04** — Drag and resize interactions handle both touch events (Capacitor mobile) and mouse events (Tauri desktop) via unified pointer event handlers
  - Delivered: Phase 09 — setPointerCapture + window pointermove/pointerup/pointercancel

## EDIT — Tap to Edit

- [x] **EDIT-01** — Tapping a task block (distinct from starting a drag) opens a bottom sheet pre-filled with the task's current title, startAt, and duration
  - Delivered: Phase 10 — useDragToReschedule onTap callback, useTaskSheet openEdit, TaskSheet

- [x] **EDIT-02** — Saving from the edit sheet updates the task optimistically in the timeline and syncs to the backend, reverting on failure
  - Delivered: Phase 10 — useNativeTasks.update → PATCH → reloadFeed

## QC — Quick-Create Input UX

- [x] **QC-01** — Time input in the create/edit sheet uses a scroll-wheel picker (hour and minute columns) rather than a text field
  - Delivered: Phase 10 — react-mobile-picker, TimeSlotPicker adapter

- [x] **QC-02** — Duration input uses a stepper control (tap + / − in 15-minute increments) with a display showing the selected duration
  - Delivered: Phase 10 — DurationPicker (mobile scroll-wheel + desktop chip+number fallback)

## VIS — Timeline Visual Polish

- [x] **VIS-01** — Each task block renders with a semi-transparent fill and a 3px left accent in the task's assigned color
  - Delivered: Phase 12 — DraggableTimeBlock containerStyle: borderColor + backgroundColor+'20', border-l-[3px]

- [x] **VIS-02** — Each task has a `color` field (hex string); users can set it from a color palette in the create/edit sheet; new tasks receive a default color
  - Delivered: Phase 12 — NativeTask.color Prisma field, PATCH handler, TaskSheet PALETTE + hex input

- [x] **VIS-03** — Task blocks optionally display an emoji or short icon prefix before the title when the task has an `icon` field set
  - Delivered: Phase 12 — NativeTask.icon, FeedItem.icon, DraggableTimeBlock icon render, TaskSheet icon field

- [x] **VIS-04** — Task blocks have a subtle drop shadow (e.g. `shadow-sm`) that visually elevates them above the timeline grid
  - Delivered: Phase 12 — DraggableTimeBlock containerClasses `shadow-sm`

- [x] **VIS-05** — Block position and height changes animate with a 150ms ease CSS transition so drag snaps and edits feel fluid rather than instant
  - Delivered: Phase 12 — DraggableTimeBlock containerStyle `transition: top 150ms ease, height 150ms ease`

## WEEK — Weekly View Navigation

- [x] **WEEK-01** — Weekly view has prev/next navigation controls to move between weeks
  - Delivered: Phase 11 — WeekNavHeader (prev/next buttons), useWeeklyPlanner weekStart state

- [x] **WEEK-02** — A "Today" button in the weekly view returns to the current week from any week offset
  - Delivered: Phase 11 — WeekNavHeader Today button resets weekStart to getWeekStart(new Date())

## NAV — App Navigation Restructure

- [x] **NAV-01** — App uses a 3-tab bottom navigation bar: Planner | Inbox | Integrations
  - Delivered: Phase 07 — BottomTabBar component, AppLayout, App.tsx routing

- [x] **NAV-02** — Planner tab shows the daily timeline view by default, with a Day / Week toggle control within the tab
  - Delivered: Phase 07 — feed/page.tsx viewMode toggle (planner/week)

- [x] **NAV-03** — Inbox tab shows undated native tasks and integration-sourced items pending scheduling
  - Delivered: Phase 07 — /inbox route + InboxPage

- [x] **NAV-04** — Integrations tab shows connected accounts (Gmail, Microsoft, Apple Calendar) and sync status
  - Delivered: Phase 07 — /settings/integrations route wired to Integrations tab

- [x] **NAV-05** — On desktop viewport widths (≥768px), navigation renders as a left sidebar instead of a bottom tab bar
  - Delivered: Phase 07 — Sidebar component with md: breakpoint in AppLayout

## CANVAS — Unified TimelineCanvas

- [x] **CANVAS-01** — A single `TimelineCanvas` component replaces both `DailyPlannerView` and `WeeklyPlannerView`; the Day/Week toggle passes a `columns` prop (1 or 7) — no component swap
  - Delivered: Phase 13 — TimelineCanvas.tsx, DailyPlannerView + WeeklyPlannerView deleted

- [x] **CANVAS-02** — The time axis (hour labels) is always pinned to the left side, shared across all columns in both Day and Week modes
  - Delivered: Phase 13 — structural flex: 48px `shrink-0` time axis column always on left

- [x] **CANVAS-03** — In week mode, each day column has a header with weekday abbreviation and date; the current day's column is highlighted
  - Delivered: Phase 13 — TimelineCanvas week mode column headers, `isToday` bg/border highlight

- [x] **CANVAS-04** — Task blocks in narrow week columns truncate title text and hide the time label when the block height falls below 28px
  - Delivered: Phase 13 — showTimeRange threshold 36→28, compact prop on DraggableTimeBlock

- [x] **CANVAS-05** — Toggling between Day and Week modes transitions the column layout with a 200ms ease animation
  - Delivered: Phase 13 — `transition-all duration-200 ease` on week column containers
