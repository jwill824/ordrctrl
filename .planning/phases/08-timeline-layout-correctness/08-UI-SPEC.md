# Phase 08 — UI Design Contract

> Visual and interaction contract for Phase 08: Timeline Layout Correctness.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase goal:** The daily timeline accurately represents every task's duration and time
> position as a spatial fact — a 30-minute task occupies exactly half the vertical space
> of a 1-hour task, and a task at 9:00 AM sits at the 9 AM mark with zero offset.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — pure Tailwind CSS utility classes + inline `style={{}}` for runtime pixel values |
| Preset | not applicable |
| Component library | none (vanilla React + Tailwind) |
| Icon library | inline SVG (stroke-based, 1.5 stroke width, round caps/joins) |
| Font | Inter via `var(--font-inter)` CSS custom property |

**Styling rule (locked from Phase 07):** Tailwind utility classes for all static visual properties
(colors, borders, padding, font sizes, font weights). Inline `style={{}}` ONLY for runtime-computed
pixel values: `top`, `height`, `scrollTop`. No `@apply`. No CSS variables set in component files.

_Source: codebase scan — `DailyPlannerView.tsx` line 9 `HOUR_HEIGHT = 64`, `PlannerTimeBlock.tsx` lines 15–16_

## Spacing Scale

Inherited from Phase 07. No changes.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge positioning |
| sm | 8px | Block internal padding, right gutter |
| md | 16px | Default element padding |
| lg | 24px | Section breaks (e.g. unscheduled section `mt-6`) |
| xl | 32px | Major layout breaks |
| 2xl | 48px | Time-axis left gutter width (`w-12` = 48px) |
| 3xl | 80px | **`PX_PER_HOUR` constant — one hour = 80px of vertical space** |

Exceptions:
- **`PX_PER_HOUR = 80`** — not an 8-point spacing token; it is a time-to-pixel conversion constant.
  Current code uses 64px/hr (`HOUR_HEIGHT = 64` in `DailyPlannerView.tsx`). This phase raises it to
  **80px/hr** for spatial clarity and tappable block heights.
- **Minimum block height floor = 24px** — any task shorter than ~18 minutes is clamped to 24px.
  This floor does NOT affect LAYOUT-01 compliance: a 30-minute task computes to 40px (> 24px floor)
  and a 1-hour task computes to 80px; 40 is exactly half of 80.
- Block left gutter: **48px fixed** (`w-12`) for time-axis labels. Task blocks begin at `left-14` (56px).
- Block right margin: **8px** (`right-2`).

## Component Contracts

### 1. Timeline Layout Constants

These constants are the source of truth for all pixel math in this phase. They must be defined
once and imported wherever time-to-pixel conversion is performed.

```ts
// frontend/src/components/timeline/timelineConstants.ts (new file)
export const PX_PER_HOUR = 80;           // 1 hour = 80px of vertical space
export const TIMELINE_START_HOUR = 0;    // axis begins at midnight (00:00)
export const TIMELINE_HOURS = 24;        // full 24-hour axis
export const TIMELINE_HEIGHT = TIMELINE_HOURS * PX_PER_HOUR; // 1920px total
export const BLOCK_MIN_HEIGHT = 24;      // minimum tappable block height (px)
export const TIME_LABEL_WIDTH = 48;      // w-12 gutter for hour labels (px)
```

### 2. DailyPlannerView — Timeline Container

**Outer wrapper (sets CSS variable for any consumer that needs it):**
```tsx
<div style={{ ['--hour-height' as string]: `${PX_PER_HOUR}px` }}>
```

**24-hour axis container:**
```tsx
<div
  className="relative w-full overflow-x-hidden"
  style={{ height: `${TIMELINE_HEIGHT}px` }}   // 1920px
>
```

`height` must be inline style — it is a runtime-computed value (`TIMELINE_HOURS * PX_PER_HOUR`).

### 3. Hour Markers (Time Axis)

One row per hour, 0–23. Each row:

```tsx
<div
  key={h}
  className="absolute left-0 right-0 border-t border-zinc-100"
  style={{ top: h * PX_PER_HOUR }}    // inline style: runtime pixel position
>
  <span className="absolute left-0 top-[-0.6rem] w-12 text-right pr-2 text-[0.65rem] text-zinc-400 leading-none select-none">
    {h === 0 ? '12am' : h < 12 ? `${h}am` : h === 12 ? '12pm' : `${h - 12}pm`}
  </span>
</div>
```

**Pixel math for label alignment:**
- Border-top lands at exactly `h * PX_PER_HOUR` from the container top.
- `top: -0.6rem` = −9.6px offsets the label text upward so the baseline sits just above the border.
- At `PX_PER_HOUR = 80` (up from 64) the 80px row height makes label-to-label spacing comfortable; no
  overlap at any zoom level on a standard 390px-wide mobile viewport.

### 4. PlannerTimeBlock — Block Height and Top Formulas

**Height formula (LAYOUT-01 contract):**
```tsx
const height = Math.max(
  (item.durationMinutes / 60) * PX_PER_HOUR,
  BLOCK_MIN_HEIGHT
);
// style={{ height }}
```

Verified correctness:
| Duration | Computed | Floor applied? | Result |
|----------|----------|----------------|--------|
| 30 min | 40px | No (40 > 24) | **40px** |
| 60 min | 80px | No | **80px** |
| 15 min | 20px | Yes (20 < 24) | **24px** |
| 10 min | ~13px | Yes | **24px** |

A 30-minute block is **exactly half** the height of a 1-hour block: 40px vs 80px. ✓ (LAYOUT-01)

**Top formula (LAYOUT-02 contract):**
```tsx
const start = new Date(item.startAt!);
const totalMinutes = start.getHours() * 60 + start.getMinutes();
const top = (totalMinutes / 60) * PX_PER_HOUR;
// style={{ top }}
```

Verified correctness:
| Start time | totalMinutes | top |
|------------|-------------|-----|
| 00:00 (midnight) | 0 | 0px |
| 09:00 AM | 540 | 720px (= 9 × 80) |
| 09:30 AM | 570 | 760px (= 9.5 × 80) |
| 12:00 PM | 720 | 960px (= 12 × 80) |

A task at 09:00 AM has `top = 720px`. The 9 AM hour marker is drawn at `9 * 80 = 720px`.
Block top and axis label are co-located at the same pixel row. ✓ (LAYOUT-02)

**Complete block element:**
```tsx
<div
  className={`absolute border-l-2 border-black bg-white px-1 py-0.5 overflow-hidden ${
    compact ? 'left-0 right-0' : 'left-14 right-2 px-2 py-1'
  } ${item.completed ? 'opacity-40' : ''}`}
  style={{ top, height }}             // ONLY these two values are inline
>
  <div className={`font-semibold text-black leading-tight truncate ${
    compact ? 'text-[0.6rem]' : 'text-[0.7rem]'
  } ${item.completed ? 'line-through' : ''}`}>
    {item.title}
  </div>
  {!compact && height >= 36 && (
    <div className="text-[0.65rem] text-zinc-400 leading-tight mt-0.5">
      {formatLocalTime(item.startAt!)}
      {item.endAt ? ` – ${formatLocalTime(item.endAt)}` : ''}
    </div>
  )}
</div>
```

### 5. Current-Time Indicator

Positioned with the same time-to-pixel formula as task blocks. Uses a `ref` for auto-scroll targeting.

**Position formula:**
```tsx
const nowMinutes = now.getHours() * 60 + now.getMinutes();
const nowTop = (nowMinutes / 60) * PX_PER_HOUR;
// style={{ top: nowTop }}
```

**Rendered element:**
```tsx
<div
  ref={currentTimeRef}
  className="absolute left-0 right-0 z-10 pointer-events-none"
  style={{ top: nowTop }}             // inline style: runtime pixel position
>
  <div className="absolute left-12 right-0 h-px bg-red-500" />
  <div className="absolute left-11 w-2 h-2 rounded-full bg-red-500 -translate-y-[3px]" />
</div>
```

The horizontal red line spans from the time-label gutter boundary (`left-12` = 48px) to the right
edge. The leading dot sits at `left-11` (44px) so it straddles the gutter edge and reads as "on" the
time axis line.

### 6. Auto-Scroll on Mount (LAYOUT-03)

**Behavior:** On initial render, the planner viewport automatically centers on the current time
without any user gesture.

**Implementation — approved pattern:**
```tsx
const currentTimeRef = useRef<HTMLDivElement>(null);

useEffect(() => {
  currentTimeRef.current?.scrollIntoView({ block: 'center' });
}, []);   // empty dep array = fires once on mount
```

`scrollIntoView({ block: 'center' })` walks up the DOM to find the nearest scrollable ancestor
(the `<div className="flex-1 overflow-y-auto ...">` in `feed/page.tsx`) and sets its `scrollTop`
such that the `currentTimeRef` element is vertically centered in the viewport. This is equivalent to
the explicit formula: `scrollTop = nowTop - scrollContainer.clientHeight / 2`.

**Why `scrollIntoView` is preferred over the explicit formula here:**
- `currentTimeRef` is a zero-height positioned div, so `scrollIntoView({ block: 'center' })` centers
  the viewport on exactly `nowTop`.
- No need to thread a `scrollContainerRef` prop through the component tree.
- Fires after paint, ensuring layout is complete before scrolling.

**Timing constraint:** The `useEffect` with `[]` deps fires after the first paint. The absolute
positioning of the current-time indicator is set via inline style at render time (not deferred), so
`scrollIntoView` sees the correct position on first call. ✓

**Edge cases:**
- If `now` is between 00:00–01:00 (early morning): `nowTop` < 80px. `scrollIntoView({ block: 'center' })`
  scrolls to top (clamped). Acceptable — user sees the start of the day.
- If `now` is between 23:00–23:59 (late night): `nowTop` > 1840px. `scrollIntoView` scrolls to
  near the bottom. Acceptable.

## Pixel-Math Verification Table

Quick reference for executor to spot-check the implementation:

| Scenario | Formula | Expected px |
|----------|---------|-------------|
| Hour marker at 9 AM | `9 * 80` | `top: 720px` |
| 30-min task at 9:00 AM | `top: 720, height: 40` | block occupies 720–760px |
| 1-hour task at 9:00 AM | `top: 720, height: 80` | block occupies 720–800px |
| 30-min block is half of 1-hour block | `40 / 80` | **0.5 — exact** |
| Current time at 9:30 AM | `(9*60+30)/60 * 80 = 570/60 * 80` | `top: 760px` |
| Timeline total height | `24 * 80` | `1920px` |
| Viewport center (typical 844px device, sub-header 44px) | `nowTop - (844 - 44 - 56) / 2` | ≈ `nowTop - 372px` |

_The last row (viewport center) is illustrative. `scrollIntoView({ block: 'center' })` computes this
automatically from the actual scroll container height at runtime._
