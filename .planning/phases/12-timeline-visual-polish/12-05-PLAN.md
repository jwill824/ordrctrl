    **backend/tests/unit/feed.service.color.test.ts:**

    Mirror the pattern from `feed.service.test.ts`. Test the pure color/icon resolution logic by extracting it into helper functions the same way the existing file does (no Prisma mock needed for pure functions):

    1. `resolveColor(overrideValue: string | null | undefined): string` — returns the override value when non-null/non-undefined, else `'#3B82F6'`. Test: override value `'#EF4444'` → `'#EF4444'`; override null → `'#3B82F6'`; override undefined → `'#3B82F6'`.
    2. `resolveIcon(overrideValue: string | null | undefined): string | null` — returns override value or `null`. Test: `'🎯'` → `'🎯'`; null → null; undefined → null.
    3. Native task: `task.color ?? '#3B82F6'` and `task.icon ?? null`. Test: task with `color: '#22C55E'` → `'#22C55E'`; task with `color: null` → `'#3B82F6'`.

    These are simple pure-function tests; no mocking required. Follow the `describe / it / expect` structure from the existing file.

    **backend/tests/contract/tasks.color.contract.test.ts:**

    Mirror the boilerplate from `feed.test.ts` (createApp, supertest, beforeAll/afterAll, `if (!request) return` guard pattern). Test the color field on the task PATCH route:

    1. `PATCH /api/tasks/:id` returns 401 when unauthenticated — `expect(res.status).toBe(401)`
    2. `PATCH /api/tasks/:id` with body `{ color: 'not-a-hex' }` returns 422 — tests the regex validator
    3. `PATCH /api/tasks/:id` with body `{ color: '#EF4444' }` returns 401 (auth) or 404/200 (if auth were present) — confirms the route parses color without crashing (the 401 path is enough without a real session)

    For test 2: since the route validates before auth check — confirm by reading tasks.routes.ts. If auth is checked first, the 401 response will prevent the 422 path. In that case, note the limitation in a comment and only assert 401. Do not try to create a real session in contract tests.

    **backend/tests/contract/feed.override.contract.test.ts:**

    Same boilerplate. Test the new `PATCH /api/feed/:itemId/override` route:

    1. Returns 401 when unauthenticated for a valid itemId: `sync:00000000-0000-0000-0000-000000000000`
    2. Returns 401 (not 404) for a native itemId: `native:00000000-0000-0000-0000-000000000000` — the auth guard fires before the itemId prefix check, so 401 is correct
    3. Unauthenticated request with malformed body returns 401 (auth guard fires first)

    Note: The `if (!request) return` guard handles environments without a running DB (same pattern as existing contract tests). All tests should pass in CI without a real DB by hitting the 401 path.

    After writing all three files, run the full backend test suite:
