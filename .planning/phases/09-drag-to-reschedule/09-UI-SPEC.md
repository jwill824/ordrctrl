# Phase 09 — UI Design Contract

> Visual and interaction contract for Phase 09: Drag to Reschedule.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase goal:** Users can drag task blocks vertically to reschedule them, and drag the bottom
> edge to resize duration — on both mobile (touch) and desktop (mouse) — with 15-minute snap
> intervals and optimistic persist with revert-on-failure.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — pure Tailwind CSS utility classes + inline `style={{}}` for runtime pixel values |
| Preset | not applicable |
| Component library | none (vanilla React + Tailwind) |
| Icon library | inline SVG (stroke-based, 1.5 stroke width, round caps/joins) |
| Font | Inter via `var(--font-inter)` CSS custom property |

**Styling rule (locked from Phase 07/08):** Tailwind utility classes for all static visual
properties. Inline `style={{}}` ONLY for runtime-computed pixel values: `top`, `height`, and
drag-state transform/shadow overrides. No `@apply`. No CSS variables set in component files.

_Source: Phases 07 + 08 UI-SPEC, locked design system decision._

## Spacing Scale

Inherited from Phase 07/08. No new tokens added. Exceptions specific to this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge positioning |
| sm | 8px | Block internal padding, right gutter |
| md | 16px | Default element padding |
| lg | 24px | Section breaks |
| xl | 32px | Major layout breaks |
| 2xl | 48px | Time-axis left gutter width (`w-12` = 48px) |
| 3xl | 80px | `PX_PER_HOUR` — one hour = 80px vertical |

**Phase 09 exceptions:**

| Measurement | Value | Rationale |
|------------|-------|-----------|
| Snap interval (px) | **20px** | `(15 min / 60) * 80px/hr = 20px` — 15-min grid in pixels |
| Drag intent threshold | **8px** | 2 × 4px — pointer must move ≥ 8px before drag declared |
| Resize handle hit zone height | **20px** | 5 × 4px — bottom of every block; not 44px (accepted tradeoff — see note) |
| Resize visual pill height | **4px** | `h-1` — subtle, appears only when block is hovered/active |
| Resize visual pill width | **32px** | `w-8` — centered horizontal pill in handle zone |
| Drag elevated z-index | **z-50** | Float above normal blocks (z-10) and now-indicator (z-10) during drag |
| Revert animation duration | **300ms** | `transition-[top,height] duration-300 ease-out` on API failure |
| Error tint duration | **1500ms** | Red border lingers post-revert, then fades back to blue |

**Resize touch target note:** A 44px touch target is the platform accessibility guideline but is
not achievable for the resize handle at the bottom of blocks at 80px/hr. A 15-minute task block
computes to 20px height (floored to 24px). The 20px resize zone is the maximum possible without
covering the entire block.
**Accepted design tradeoff:** The resize interaction targets are smaller than 44px on short blocks.
Mitigation: the 15-min snap means the smallest meaningful task is already 20px → 24px floor, and
the interaction is forgiving — dragging anywhere in the bottom 20px of the block triggers resize.
Very short tasks (< 30min) are edge cases where resize precision matters less.

|-------|-------------|------------|--------|

- Idle block: pill is `opacity-0` (invisible)
- On `pointerenter` (hover) or during drag-resize: pill is `opacity-100` (`bg-blue-300`)
- On mobile (touch), the pill is always `opacity-60` so users can see the resize affordance

### 2. Block Visual States

The `DraggableTimeBlock` component is the enhanced replacement for `PlannerTimeBlock` within
`DailyPlannerView`. It inherits the existing block visual from Phase 08 and adds drag state layers.

#### 2a. Idle State (inherited from Phase 08)

```tsx
<div
  className={`absolute border-l-[3px] border-blue-500 bg-blue-50 rounded-r px-2 py-1 overflow-hidden left-14 right-2 ${
    item.completed ? 'opacity-40' : ''
  }`}
  style={{ top, height }}
>
  {/* title + time range — unchanged from Phase 08 */}
  <div className="absolute bottom-0 left-0 right-0 h-5 flex items-end justify-center pb-1 cursor-ns-resize">
    <div className="w-8 h-1 bg-blue-300 rounded-full opacity-0 md:group-hover:opacity-100 touch:opacity-60" />
  </div>
</div>
```

_Note: `touch:opacity-60` is a conceptual shorthand. In implementation, use a state flag
`isTouchDevice` set once on first `touchstart` event to conditionally render the pill visible._

#### 2b. Drag-Move Active State

Applied when the user has initiated a drag-move gesture (moved ≥ 8px vertically from drag origin
on the block body, excluding the bottom 20px resize zone).

**Changes from idle:**
- `shadow-md` added
- `opacity-90` on the block
- `cursor: grabbing` on document body (via `useEffect` during drag)
- `z-index: 50` via inline style (must override absolute stacking context)
- `touch-action: none` on the drag container (via inline style or data attribute)
- `transition: none` — no CSS transitions during active drag (smooth tracking)

```tsx
<div
  className="absolute border-l-[3px] border-blue-500 bg-blue-50 rounded-r px-2 py-1 overflow-hidden left-14 right-2 shadow-md opacity-90"
  style={{ top: dragTop, height, zIndex: 50, touchAction: 'none', transition: 'none' }}
>
```

**The block at its original position is NOT shown during drag-move.** The dragged block moves
with the pointer; no ghost remains at the origin.

#### 2c. Drag-Resize Active State

Applied when the user is dragging the bottom edge resize handle.

**Changes from idle:**
- `shadow-sm` added
- `cursor: ns-resize` on document body during resize
- `z-index: 20` (slightly elevated, not full z-50 since position doesn't change)
- `touch-action: none`
- `transition: none`
- Resize handle pill is `opacity-100`

```tsx
<div
  className="absolute border-l-[3px] border-blue-500 bg-blue-50 rounded-r px-2 py-1 overflow-hidden left-14 right-2 shadow-sm"
  style={{ top, height: dragHeight, zIndex: 20, touchAction: 'none', transition: 'none' }}
>
```

#### 2d. Error Tint State (post-revert, 1500ms window)

Applied after revert animation completes (API persist failed). Transitions from
`border-blue-500` to `border-red-400`, then after 1500ms transitions back.

```tsx
<div
  className={`absolute border-l-[3px] rounded-r px-2 py-1 overflow-hidden left-14 right-2 bg-blue-50 ${
    isErrorTint ? 'border-red-400' : 'border-blue-500'
  }`}
  style={{ top, height, transition: 'border-color 200ms ease-out' }}
>
```

#### 2e. Revert Animation State

Applied on API failure. Block position animated from drag-release position back to original.
CSS transition on `top` and `height`:

```tsx
// During revert: style includes transition
style={{
  top: originalTop,   // set back to original value
  height: originalHeight,
  transition: 'top 300ms ease-out, height 300ms ease-out'
}}
```

### 3. Resize Handle

The resize handle is an invisible-by-default affordance zone at the bottom of every task block.

**Anatomy:**
```
┌─────────────────────────────────────┐ ← top of block
│  title text                         │
│  time range (if height ≥ 36px)      │
│                                     │
├──────── resize handle zone ─────────┤ ← (height - 20px) from top
│     [  ▬▬▬▬▬▬▬ pill ▬▬▬▬▬▬▬  ]     │ ← visible pill (4px tall, 32px wide)
└─────────────────────────────────────┘ ← bottom of block (resize handle zone = 20px tall)
```

**Resize handle markup:**

```tsx
<div
  className="absolute bottom-0 left-0 right-0 h-5 flex items-end justify-center pb-1 cursor-ns-resize select-none"
  onPointerDown={handleResizePointerDown}
  aria-label="Drag to resize duration"
  role="slider"
  aria-valuemin={15}
  aria-valuemax={240}
  aria-valuenow={item.durationMinutes}
  aria-valuetext={`${item.durationMinutes} minutes`}
>
  <div className={`w-8 h-1 rounded-full bg-blue-300 transition-opacity duration-150 ${
    isResizing ? 'opacity-100' : isTouchDevice ? 'opacity-60' : 'opacity-0 group-hover:opacity-100'
  }`} />
</div>
```

The block container must have `className="... group"` so `group-hover:opacity-100` works on the pill.

**On blocks with `height < 36px`:** The resize handle zone `h-5` (20px) would consume > 50% of
the block. This is acceptable — on sub-36px blocks the entire bottom half is effectively a resize
handle, and the drag body (for move) is the upper portion.

### 4. Block Anatomy — Zone Map

```
┌──────────────────────────────────────────┐
│                                          │ ← onPointerDown here → drag-MOVE zone
│  DRAG-MOVE zone (block body)             │   (pointerMove ≥ 8px declares drag)
│  (top: 0 to bottom: calc(100% - 20px))   │
│                                          │
│  [title][time range if visible]          │
│                                          │
├──────────────────────────────────────────┤
│  RESIZE zone (bottom 20px)               │ ← onPointerDown here → drag-RESIZE
│  [    ▬▬▬▬ resize pill ▬▬▬▬    ]         │
└──────────────────────────────────────────┘
```

**Tap disambiguation (critical for Phase 10 coexistence):**
- `pointerDown` fires → start a timer (200ms) and record `startY`
- If `pointerUp` fires with < 8px movement AND < 200ms elapsed → this is a **tap** → pass to
  click handler (Phase 10 edit sheet will listen here)
- If pointer moves ≥ 8px from `startY` → cancel tap timer → declare drag-move
- If `pointerDown` fires on resize zone → immediately enter drag-resize (no tap ambiguity needed
  since resize zone is not a tap target)

_Phase 10 (Tap to Edit) relies on the tap path established here. The click handler must be a
no-op in Phase 09 (or log a console note) — Phase 10 will wire it to the edit sheet._

### 5. Snap Calculation

All snap computation is pure arithmetic. No DOM reads during drag.

```ts
// Snap start time during drag-move
const snapToGrid = (minutes: number): number =>
  Math.round(minutes / SNAP_MINUTES) * SNAP_MINUTES;

// Drag-move: new start time
const deltaMinutes = (currentY - pointerStartY) / PX_PER_HOUR * 60;
const rawNewStart = originalStartMinutes + deltaMinutes;
const snappedStart = Math.max(0, Math.min(snapToGrid(rawNewStart), 24 * 60 - MIN_DRAG_DURATION_MINUTES));
const newTop = (snappedStart / 60) * PX_PER_HOUR;

// Drag-resize: new duration
const deltaMinutes = (currentY - pointerStartY) / PX_PER_HOUR * 60;
const rawNewDuration = originalDurationMinutes + deltaMinutes;
const snappedDuration = Math.max(MIN_DRAG_DURATION_MINUTES, snapToGrid(rawNewDuration));
const newHeight = Math.max(BLOCK_MIN_HEIGHT, (snappedDuration / 60) * PX_PER_HOUR);
```

**Boundary clamping:**
- `snappedStart` must be ≥ 0 (midnight) and ≤ 23:45 (last valid 15-min slot before midnight)
- `snappedDuration` must be ≥ 15 minutes
- `snappedStart + snappedDuration` must be ≤ 24:00 (no task overflows past midnight)

### 6. Pointer Event Strategy (DRAG-04)

Use unified pointer events throughout. No separate touch/mouse handler paths.

```tsx
// On the drag-move zone (block body)
onPointerDown={handleMovePointerDown}

// On the resize zone
onPointerDown={handleResizePointerDown}

// On document (attached during active drag)
document.addEventListener('pointermove', handlePointerMove, { passive: false })
document.addEventListener('pointerup', handlePointerUp)
document.addEventListener('pointercancel', handlePointerCancel)
```

**`setPointerCapture` on drag start:** Call `element.setPointerCapture(event.pointerId)` on
`pointerDown` for both move and resize. This routes all subsequent pointer events to the element
even if the pointer leaves it (critical for fast drag gestures on mobile).

**`e.preventDefault()` in `pointermove`:** Must call `e.preventDefault()` in `pointermove` when
drag is active to prevent touch scroll interfering with drag. Requires `{ passive: false }` on
the listener.

**`touch-action: none`** on the scroll container during active drag: set via inline style on
`DailyPlannerView`'s scroll container div when any drag is active, to suppress browser scroll
interference at the container level.

### 7. Optimistic Update + Revert Flow (DRAG-03)

```
pointerUp
  │
  ├─ Commit dragTop/dragHeight to React state (block renders at new position)
  ├─ Fire API mutation: PATCH /tasks/{id} { startAt, durationMinutes }
  │
  ├─ API succeeds → idle state, no visual change needed (already at correct position)
  │
  └─ API fails
       ├─ Set transition: 'top 300ms ease-out, height 300ms ease-out'
       ├─ Set top/height back to originalTop/originalHeight (triggers CSS transition)
       ├─ After 300ms → clear transition, enter error-tint state (border-red-400)
       └─ After 1500ms → clear error-tint state, return to fully idle
```

**No toast notification.** The revert animation IS the failure signal. The red border tint
reinforces the failure state without introducing new UI chrome. This is consistent with the
codebase's existing non-toast error pattern (no global toast infrastructure visible in codebase
scan).

## Pixel-Math Verification Table

Quick reference for executor to verify snap math:

| Scenario | Formula | Expected |
|----------|---------|----------|
| Snap interval in pixels | `(15/60) * 80` | **20px** |
| Drag moves 20px → time delta | `(20/80) * 60` | **15 min** (one snap interval) |
| Drag moves 10px → snapped | `round(10/20) * 20 = round(0.5) * 20` | **20px** (rounds to 1 interval) |
| 15-min task height after drag | `max((15/60)*80, 24)` | **24px** (floor applied) |
| 30-min task height after drag | `max((30/60)*80, 24)` | **40px** |
| Resize +1 snap (15min) | `height + 20px` | block grows 20px |
| Task clamped to midnight end | `snappedStart + duration ≤ 1440 min` | no overflow |
| Task at 23:45 (latest start) | `(23*60+45)/60 * 80` | `top: 1900px` |

## Responsive Behavior

| Viewport | Drag-Move | Resize Handle | Error Tint |
|----------|-----------|---------------|------------|
| Mobile (< 768px, touch) | `onPointerDown` + `setPointerCapture` | Pill always `opacity-60` | `border-red-400` 1500ms |
| Desktop (≥ 768px, mouse) | `onPointerDown` + `setPointerCapture` | Pill `opacity-0` → `opacity-100` on hover | `border-red-400` 1500ms |

Both inputs use identical pointer event handlers — no platform branching. The only visual
difference is the resize pill visibility (always visible on touch, hover-only on mouse).

**`isTouchDevice` detection:** Set a module-level flag `let hasTouched = false` on first
`touchstart` event fired anywhere in the document. Use this flag in `DraggableTimeBlock` to
choose the pill opacity class. No `navigator.userAgent` parsing.
