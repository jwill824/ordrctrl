    Phase 09 complete — drag-to-reschedule and drag-to-resize implemented end-to-end:

    2. `DraggableTimeBlock` component — 6 visual states (idle / drag-move / drag-resize / persisting / reverting / error-tint), resize handle
    3. `DailyPlannerView` — renders DraggableTimeBlock, passes onReschedule/onResize callbacks
    4. `feed/page.tsx` — handleReschedule/handleResize with native: guard, isDragActive touchAction toggle
    5. `useNativeTasks.update` — expanded to accept startAt and duration fields
    6. Full test suite: GREEN (all unit tests pass)
  </what-built>
  <how-to-verify>
    Start the dev server:
    ```
    cd frontend && pnpm dev
    ```
    Open http://localhost:5173 in your browser (or run on device via Capacitor for touch test).

    **Test 1 — Drag move (DRAG-01):**
    1. Navigate to the Planner tab
    2. Ensure at least one native task is visible on the timeline
    3. Click and drag a task block vertically — the block should follow the pointer
    4. Observe: block snaps to 15-minute grid positions during drag (not pixel-perfect smooth)
    5. Release — task should appear at new time position and persist after page refresh
    6. Expected: start time changes to nearest 15-minute interval

    **Test 2 — Drag resize (DRAG-02):**
    1. Hover over a task block — a small pill should appear at the bottom edge (desktop: on hover; mobile: always visible at 60% opacity)
    2. Drag the bottom edge down — block height should grow in 15-minute increments
    3. Drag up — block height shrinks but never below 15 minutes (24px floor)
    4. Release — new duration should persist

    **Test 3 — Revert animation (DRAG-03):**
    1. Disconnect from the backend (e.g., stop the backend server or toggle network off in DevTools)
    2. Drag a task to a new position and release
    3. Expected: block animates back to original position over ~300ms, then shows a red left border for ~1500ms, then returns to normal blue border
    4. Reconnect the backend

    **Test 4 — Tap disambiguation:**
    1. Short-tap a task block (quick click/tap, < 200ms, < 8px movement)
    2. Expected: nothing happens in Phase 09 (no-op tap — Phase 10 will wire the edit sheet)
    3. Block should NOT be considered "dragged" and should NOT call the reschedule API

    **Test 5 — Sync item no-op:**
    1. If any sync items (Google Calendar events, Gmail items) are visible on the planner
    2. Try dragging one — should move visually but NOT fire a PATCH to the backend
    3. Check the Network tab — no PATCH /api/tasks/:id call for the sync item

    **Test 6 — Mobile touch (if Capacitor device available):**
    1. Run `cd mobile && npx cap run ios` (or android)
    2. Verify touch drag works without page-scroll interfering with the drag gesture
    3. Verify resize handle is visible at 60% opacity without hovering

    **Regression check:**
    1. Confirm existing planner functionality works: task completion, dismiss, source filter pills
    2. Navigate to week view — WeeklyPlannerView should be unaffected (uses PlannerTimeBlock, not DraggableTimeBlock)
  </how-to-verify>
